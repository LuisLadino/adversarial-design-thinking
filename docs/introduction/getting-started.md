# Getting Started

This site teaches adversarial prompt engineering through a design thinking lens. Here's how to use it.

---

## Who this helps

**Red teamers testing AI models** — The exercises help you think through your approach before you start prompting. Personas push you past your default mental model. Ideation generates vectors you wouldn't reach through habit.

**Teams coordinating testing** — Journey maps make multi-turn attacks reproducible. Personas create shared vocabulary. The findings format gives everyone the same structure for documenting results.

**Anyone reporting to stakeholders** — Technical severity scores don't always land. The Document Findings exercise helps describe impact in terms that drive action.

---

## Site structure

**[Techniques](/techniques)** — The building blocks. Understand what mechanisms exist and why they work before trying to use them.

**[Crafting](/crafting-prompts)** — How to combine techniques into effective attacks.
- *Per-Request Prompts* — Bypass safety on one specific request
- *System Jailbreaks* — Persistent configurations that remove safety entirely

**[Practice](/exercises)** — Apply what you learned.
- *Exercises* — Structured activities for planning, ideation, execution, and reflection
- *Workshop* — Full facilitated session combining multiple exercises

---

## Reading order

**New to adversarial prompting:**
1. Read [Mindset](/) to understand the philosophy
2. Browse [Techniques](/techniques) to see what mechanisms exist
3. Study [Crafting Prompts](/crafting-prompts) to learn composition
4. Use [Exercises](/exercises) to practice

**Already experienced:**
1. Skim [Mindset](/) for the design thinking framing
2. Jump to [Techniques](/techniques) for the reference
3. Use exercises when you're stuck or want to be more systematic

**Working with a team:**
1. Run the [Workshop](/workshops/red-team-kickoff) together
2. Use shared personas and journey maps for consistency
3. Standardize on the findings format for reporting
